# 0003. audit v2 分期：最小集先行，哈希链降 P2

> 一句话：audit v2 先落无链最小集；哈希链降 P2，以链外锚为前置。

- 状态：已接受（2026-10-24 拍板）
- 关联：`docs/rebuild/07-audit-log-design.md`（参考非权威）
- 分工：本文留历史取舍；现行规则以 `docs/约束索引.md` 为准。

## 背景

`docs/rebuild/07-audit-log-design.md` 的提案里含哈希链防篡改。2026-10 架构评审专项复核的结论：无链外锚的哈希链对「整尾重写」无效——链的校验值自己也存在被改的同一份存储里，纯本地自洽已被 07 自己的论证证伪，边际收益低。同时 DSH 本地插件的定位排除重型方案：不上数据库、不引入密钥管理、体积依赖敏感、审计只追加。

## 决策

2026-10-24 拍板：

1. P1-2 只落「无链最小集」：事件补 `recordId` / `runId` / `observedTs` 三字段（schema 升 2，旧文件不回改）、evidence 补 before/after 摘要（只存 sha256 与字节数，不存全文）、apply-result 补 `completeness` 三布尔（任一假则 result 必为 partial）、查询面开一条复用已有 tail/why 的路由。
2. 哈希链与检查点整体降 P2（roadmap P2-4），且以链外锚为前置：检查点文件同时追加到 git 仓库或远程验证机目录，才算完成——没有外锚的链不做。
3. 依赖重启与宿主状态的 L1/L2 事件另轮做，不进本批。

## 后果

正面：P1-2 范围收敛，不引入 canonical 编码单点实现与 audit verify 子命令的维护成本；账本先解决「记全了、打成了什么」，防篡改留给有锚的版本。

代价：防篡改为零的状态延长到 P2-4 落地；schema 2 带来新旧 JSONL 并存的读侧兼容成本（tail/why 须容忍没有新字段的旧行）；装机探针断言（行数 = auditCounts、三层各有 apply-result、completeness 全真）要到远程验证机上执行。
