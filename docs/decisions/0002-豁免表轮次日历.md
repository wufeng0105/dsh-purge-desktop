# 0002. 豁免表按轮次日历拆分，只减不增

> 一句话：豁免必须写为什么不能切、排期与前置；只减不增。

- 状态：已接受（2026-10-24 立账）
- 关联：`WORKFLOW-4`；`docs/布局约定.md` 豁免表
- 分工：本文留历史取舍；现行规则以 `docs/约束索引.md` 为准。

## 背景

`docs/布局约定.md` 的 800 行豁免表在 2026-10 架构评审时实测为只增不减（历史 +11 / −0）。13 行豁免里 11 行是「已排期拆分」，各自的前置条件不同：有的要先补 characterization 快照，有的要真机验证，有的要扩用例覆盖。没有轮次日历，豁免就是愿望清单——登记那一刻起没人再看它。

## 决策

1. 豁免行必须同时写清三件事：为什么不能切（写不出来就不是豁免，是该切的债）、排到第几轮、前置条件是什么。
2. 拆分按轮次日历推进：第 2 轮 redteam 判定 / 数据二分（store-core、score-rules、tools、ui、probe-host-patches），第 3 轮补丁引擎与宿主交接（core.js），第 4 轮导出聚合 / 安装定位 / 更新通道（index、desktop、update），第 5 轮路径探测（host/paths）。
3. 每拆一笔，豁免表减一行；登记了豁免但文件已不存在或已降到 800 行以内，由 check-file-roles 点名（死账报红）。豁免表是账本，方向只减不增。

## 后果

正面：豁免表从愿望清单变账本，每行带着可核查的排期与前置；棘轮方向（`WORKFLOW-4`）有了具体的载体。

代价：排期轮次要随实际进度维护，前置条件未满足时豁免继续冻结——冻结是显式的，比无声堆积好；characterization 快照是高投入（脱敏靶标夹具 + 临时 SQLite 库），这是为「拆分可证明行为不变」付的钱。
