# 0010. 模板串中文棘轮与基线更正：145 是迁移中间值，现行基线是 1

> 一句话：模板串中文棘轮按实测基线 1 登记，145 是迁移中间值。

- 状态：已接受（2026-10-24 S3，含一处 roadmap 与实测不符的更正）
- 关联：`WORKFLOW-4`；`scripts/cjk-count.mjs`、`test/rules-ratchet.test.mjs`
- 分工：本文留历史取舍；现行规则以 `docs/约束索引.md` 为准。

## 背景

S1 评审的盲区表写「模板串中文 cjkCombinedMatches=145，只在 measure.mjs 度量、无棘轮」，roadmap 据此提案上限 145。本轮落地时实测对不上：现行值 1，评审基线 commit（c01a8c5）上也是 1。溯源发现 145 出自 i18n 迁移轮——ast-grep 规则注释记载「本轮 cjkCombinedMatches 1091 → 145」，而迁移收尾 commit（db6938e）的消息是「1091 → 1」；评审把迁移中间值当成了基线。现存唯一命中是 `lib/client-src/dock/auth-gate.js:12` 的 AUTH_LEGAL_HTML，CONTRACT-6 要求它与 `docs/drill-auth-legal.html` 逐字节相同，是 ast-grep no-cjk 规则唯一豁免。

## 决策

1. 棘轮落地（`test/rules-ratchet.test.mjs` 新增两条，双向）：命中数不许超上限；实际值低于上限时红，逼着把上限降下来——上限过时等于棘轮失效，与 ast-grep 债务同一设计。
2. 上限按实测登记为 **1**，不按 145。依据：AGENTS.md「改数字先改实测」；roadmap 提案自己也写明「数值口径以 scripts/measure.mjs 同逻辑为准」，而该逻辑的现行输出是 1。按 145 登记会得到一个高出现值 144 的橡皮棘轮。
3. 计数口径提取为 `scripts/cjk-count.mjs`（文件清单 + 正则 + countCjk），measure.mjs 与棘轮共用一处实现——两处各写一份，漂移是迟早的。
4. rules/no-cjk 规则注释里的同域漂移一并修正：「1067 处」「1091 → 145」改为可复算的表述，`settings/sections.js`（已拆分为 policy-approval.js）路径更正。

## 后果

正面：模板串里的文案硬编码从此有双向棘轮；145 的来路写进规则注释与本文，后人不会再把它当基线。

代价：这是 roadmap 与现状对不上的一处——按纪律以实测为准执行并留痕，最终口径以指挥会话裁决为准；若裁决要回到 145（或任何高于现值的数），改 `CJK_CEILING` 一个常量加一句依据即可。
