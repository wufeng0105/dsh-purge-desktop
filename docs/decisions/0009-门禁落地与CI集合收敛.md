# 0009. 门禁落地与 CI 集合收敛：术语、豁免棘轮、verify 映射

> 一句话：三个适应度函数各自的形态选择，以及为让映射成立退役两个 CI 独有步骤。

- 状态：已接受（2026-10-24 S3）
- 关联：`TERM-1`、`WORKFLOW-4`、`CI-5`；`docs/decisions/0002`、`0004` 的后续
- 分工：本文留历史取舍；现行规则以 `docs/约束索引.md` 为准。

## 背景

S1 提案的适应度函数里，术语一致性、豁免只增不减、本地与 CI 两套「全量」再漂移三条都只有评审兜底。S3 把它们落成门禁，每个门禁先定形态再定判据。

## 决策

1. **术语门禁用独立脚本**（`scripts/check-terms.mjs`），不并入 `check-comments.mjs`——后者只扫 lib/scripts/test/bin 的 .js/.mjs 注释，覆盖不了 docs 与 .github，而 P1-4 的改词 sweep 恰恰扫的是全仓文本。白名单三处：术语账本自身（要能讨论禁词）、primer（宿主概念译名，账本三条边界第三条豁免）、`docs/rebuild/**`（冻结区按当时措辞保留），外加脚本自身（门禁要能写出它守的词）。白名单的权威在术语账本：账本不再出现某个禁用词、或不再写明 primer 豁免时，脚本 exit 2 逼决策，不静默放行。
2. **豁免棘轮用新测试文件**（`test/exemption-ratchet.test.mjs`），判据两条：工作区豁免表的文件集合是 HEAD 的子集（换名 swap 算新增），行数不超过 HEAD。拿 `git show HEAD` 对比是因为「只减不增」的方向判据只有跟已提交状态比才成立；减必须同步删行由 check-file-roles 的死账检查兜底，本测试管不许新增。
3. **verify 集合一致性用声明式映射表**（住进 `test/workflows.test.mjs`）：本地链每一步 → CI 步骤名 + 该步骤 run 块里必须出现的命令原文，外加 CI 具名步骤全表。为让「CI 独有项仅 codegen drift」成立，退役 CI 的 `Client bundle evaluates` 与 `Client bundle markers` 两步——它们的内容（client-evaluates / client-bundle 两个测试文件）都在 `npm test` 的递归发现范围内，本地与 CI 跑同一集合，单列不增加任何覆盖，只打破声明式映射。CONTRACT-5 的载体随之改为两个测试文件，不留死引用。

## 后果

正面：三个盲区都有了机械护栏，且各自带红灯测试记录；verify 映射从此有牙齿——往任何一边加门禁不改表就红。

代价：术语门禁多一个脚本与一份白名单要维护（白名单增长受 exit 2 的脱节检查盯着）；豁免棘轮依赖 git 可用（不可用时 skip 并写明，不把「没量」当「没涨」）；CI 少两个显眼步骤名，「产物求值」的可见性退回测试文件名级别——这是为映射纯粹性付的代价，评审时靠 CONTRACT-5 的编号定位。
