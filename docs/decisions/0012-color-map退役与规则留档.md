# 0012. color-map 退役：删掉没有读者的映射表，只留它教给人的规则

> 一句话：删掉没有读者的色相映射表，只留它教给人的七条配色规则。

- 状态：已接受（2026-10-25）
- 关联：`architecture/color-map.json`（本次删除）；`lib/client-src/dock/purge-css.js`；`test/color-map.test.mjs`
- 分工：本文留「为什么删、删掉的东西怎么取回」；颜色令牌的现行取值以 CSS 为准，本文件不复述。

## 背景

`architecture/color-map.json` 是 M0 期的一张「属性 × 色相」二维映射表：给定一个 CSS 属性的原始颜色，它记下该颜色应当落到哪个语义令牌。它自己第一行就写着答案的一半——`note` 原文：

> 「属性 × 色相」二维映射。生成脚本已在 2.0.0 收尾时删除，本文件只作历史对照，勿手改。

也就是说：**生产它的脚本在 2.0.0 收尾时就没了，从此没有任何东西能重算它，也没有任何东西会读它。**它之所以留到今天，只是因为「删掉一份看起来像设计资料的东西」需要一个比「看着像死重量」更硬的依据，而当时的复核把这个依据推到了后面。

本轮的取证补齐了这个依据：

- **零读者**。搜 `lib/`、`scripts/`、`bin/`、`test/`、`docs/` 五层的全部文本文件，文件名 `color-map` 零命中；全仓只有 `release-notes.md` 的中英两段叙述提到它「移进 `architecture/`」，那是历史叙述，不读它。它是数据文件而不是模块，没有「被调函数」这一层可漏——想读它就必须出现字面量路径。
- **同名测试不是它的读者**。`test/color-map.test.mjs` 里带 `color-map` 是这套样式纪律的名字：它直接解析三段 CSS（`purge-css.js`、`rewind-ui.js`、`lib/redteam/client.js`），并刻意声明「不依赖中间产物」。映射表写错而 CSS 对，那条测试照样过——这正是它当初的设计。
- **不随包发布**。`package.json` 的 `files[]` 不含 `architecture`，它从来不是交付物。
- **内容已被别处覆盖**。`buckets` 的 11 个令牌在 `purge-css.js` 的 `:root` 段逐字在场（其中 `--dshp-c-scrim` 的取值已经从 `rgba(0,0,0,.62)` 演进成 `color-mix(...)`，即这份副本在这一项上已经是过期的）；而这些令牌今天仍在用，`rewind-ui.js` 的动画段也引用其中几个。

## 决策

删除 `architecture/color-map.json`。它的规则搬进本文，它的数据不搬。

## 留档：note 与七条规则（逐字）

`note`：

> 「属性 × 色相」二维映射。生成脚本已在 2.0.0 收尾时删除，本文件只作历史对照，勿手改。

`rules` 七条，原文照抄，不改写、不合并：

1. `P1 属性族：color/fill/stroke → 前景；background*/box-shadow → 背景；border*/outline* → 边框；其余按前景`
2. `P2 前景：L<55 → text；否则 text-muted`
3. `P3 背景：alpha<1 → scrim；否则 L≥60 → bg-card；否则 bg-page`
4. `P4 边框：一律 border`
5. `P5 状态语境且 s≥35% 才进状态族：danger 345-18 / warn 18-70 / brand 130-180 / info 180-248 / accent 248-300，缝隙落 violet`
6. `P6 scrim 只收 alpha<1`
7. `P7 暖白（L>90 且 h 20-70）在背景上走 bg-card`

## 为什么只留 note 与 rules

三样东西的去向不同：

- **`note` + `rules` 是规则本体**，全仓没有第二份。删掉就等于把「某个属性当年为什么落到那个色相」的判据一起删了。
- **`buckets` 是 CSS 的副本**，而且已经是半过期的副本（见上）。留一份会漂的副本，读者还得先判断哪边新——比不留更坏。
- **`used` / `counts` / `samples` / `all` 是 M0 期的分析快照**：它们记的是「当时有哪些属性、各落了多少次」，不是规则，也不驱动任何动作。这类统计的归宿是当时的提交，不是一份永久文档。

## 怎么取回全文

删除不是不可逆——**重写历史才是**。原文仍可从 git 逐字节取回：

```
git show f923862f344fcfd309cec8ca89b74a3dae47cfc7:architecture/color-map.json
```

该 commit 是最后一次动这个路径的提交（把它移进 `architecture/` 的那一笔），其 blob 为 `65ab5b69aa85307b8865bd9a6c649633fd64d59f`，97,865 B / 4,204 行。这两个数字描述的是**一个已删除的 blob**，因此不会随仓库漂移——它们是坐标，不是现状。

## 后果

正面：仓库里少一份 4,204 行的、无人读的、已经部分过期的数据文件；「样式纪律」的判据回到它真正的载体（CSS 与 `test/color-map.test.mjs`），读者不必再判断表与 CSS 哪个新。

代价：想查「某个属性当时为什么落到那个色相」要翻 git 历史，多一步 `git show`。这是一次**删除型**改动，净删除 4,204 行、1 个文件：按 `WORKFLOW-3` 的字面阈值（单次净删除 ≤ 400 行且 ≤ 3 个文件）它超了行数那一半，而 `WORKFLOW-3` 的载体是人工评审——**本文就是那次评审的留痕**：删除对象是一个自述「勿手改」、无生成器、无读者、不随包发布的纯数据文件，且规则已逐字搬走、全文可从上面那条命令取回。若复核认为这仍应计入删除预算，处置方式是把本条提升为一次专门的评审项，而不是把文件塞回去。
