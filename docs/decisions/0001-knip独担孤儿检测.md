# 0001. knip 独担孤儿检测，检查规则一律 error

> 一句话：孤儿检测只归 knip 一家管；新增检查一律 error。

- 状态：已接受（2026-10-24 拍板）
- 关联：`DELETE-2`；`docs/约束索引.md` 风险地图
- 分工：本文留历史取舍；现行规则以 `docs/约束索引.md` 为准。

## 背景

`npm run dead`（knip）曾把 files / exports / types / duplicates / binaries / unresolved 六组报为 warn，而 knip 的退出码只累计 error 组——warn 等于没有牙齿。同时 depcruise 里还有一条 no-orphans 规则配着 12 项 pathNot 豁免：两套工具重叠管同一性质（孤儿检测），豁免理由散在表格里，什么时机该把 warn 升成 error 没有规则。这是 2026-10 架构评审认定的「门禁堆积」根因之一：决策不留痕，规则就只能靠人记。

## 决策

2026-10-24 拍板，三件事一次定死：

1. knip 六组一次升齐 error，不留 warn 缓冲期。此后新增检查默认 error；确要缓冲期，先在这里补一条新决策，不许默默加 warn。
2. depcruise 的 no-orphans 规则连同 12 项 pathNot 豁免一并退役，孤儿检测由 knip 独家承担。同一性质只许一个门禁管，重叠的两套等于双倍豁免要维护。
3. 已知盲区登记进 `docs/约束索引.md` 风险地图：被测试文件动态 `import()` 的模块（`lib/core.js`、`lib/atomic-fs.js` 等）被 knip 判为不透明，全部导出视为已引用——这些文件上新增未用导出不会让 dead 变红。靠评审兜底，S3 门禁收敛时统一重议（选项：测试改静态具名 import、给 knip 上游提 issue）。

> 后续（2026-10-24，S3）：已重议，结论见 `docs/decisions/0008-knip盲区重议.md`——本篇第 3 条的归因被实证推翻（测试文件不在 knip 图内；根因是探针脚本动态 import），盲区三文件具名后接受残余风险。

## 后果

正面：dead 有牙齿；depcruise 少一条规则加 12 项豁免，孤儿检测责任单一。

代价：放弃 warn 缓冲期，新增未用导出直接红；knip 盲区内的文件（`lib/core.js`、`lib/atomic-fs.js` 等）的死导出只能靠评审发现；红灯验收实验必须选盲区外的文件做载体——2026-10-24 的验收用 `lib/skills.js` 注入未用导出复现了 exit 1，同一实验在 `lib/atomic-fs.js` 上不红，盲区由此实证。
