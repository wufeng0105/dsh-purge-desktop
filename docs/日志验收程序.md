# 日志读法的验收程序（可复跑）

> 一句话：先引规则再答题，绕过点为零才算过。

为什么存在：以前的验收问的是「**这次改动做对了没有**」（测试绿不绿、盲读答对没有）。
> 上一次盲读四问全中，可它同时挑出十四条读法缺陷 —— 因为那位读者是**绕过读法自己推断**才答对的。
> 答案对、路径错，验收照样通过，于是读法里的坏规则活到了下一次真机。
>
> 这份程序改问法：**照着读法给的规则走，能不能得出正确结论**。答案只是结果之一，
> **路径**（他引了哪一条规则）才是判据。

## 判据（三条，缺一条就不过）

1. **每一问都要先引读法的一节**，再答题。引用格式：`依据：docs/readme-for-ai.md §<节号> —— <原文片段>`。
   没有引用的答案不计分（蒙对也不算）。
2. **路径正确**：他引的那条规则必须真的支持那个答案。引对了答案却是靠常识补的 ⇒ **不通过**；
   引用的规则本身是错的（例如旧的「末行是层结论」）⇒ **不通过**。
3. **绕过点为零**：凡是他「读法没说、我自己想出来的」，逐条记下来 —— 每一处都是读法的失败点，
   要回填到读法里；回填之前这一轮不算过。

## 材料（只给这三样，不给仓库、不给源码、不给历史对话）

| 节 | 内容 | 怎么产生 |
| --- | --- | --- |
| 一 | `docs/readme-for-ai.md` 全文 | 直接拷 |
| 二 | 一份真机 `logs/diag.jsonl` | 从装机树或取回的样本目录拷 |
| 三 | 同一台机器的 `audit/*.jsonl`（一天或多天） | 同上 |

把三节拼成一个 `input.md`（节与节之间加 `# 第二节` 这类标题），**不夹带任何仓库路径、结论、提示**。
日志原文里的绝对路径照抄 —— 那是日志内容，不是线索。

## 四问（固定，不许改成「你觉得有什么问题」）

1. 这次 apply 是谁触发的（哪个入口）？封没封？
2. 这一轮完整吗（有没有被截断）？卡在哪一步？
3. 这些改动生效了吗？下一步该试什么？
4. 新老日志怎么分？你手上这份是哪一代？

## 执行步骤

1. 起一个**新鲜上下文**的读者（顶层会话，能读文件、不许读仓库）。
2. 把上面那段提示词原样给它，等它交卷。
3. 收卷后逐问核对三件事：**答案 / 引用的节 / 有没有绕过**。
4. 把结果按下面这张表落盘（一次验收一份，文件名 `<日期>-盲读.md`）：

```
| 问 | 答案 | 引用（§） | 路径对不对 | 绕过点 | 判 |
| --- | --- | --- | --- | --- | --- |
```

5. **绕过点非空 ⇒ 把读法补上，再跑一次**；两次之间不许改动日志材料（否则两次不可比）。

## 前置自检：真机样本先过六条判据

取回样本后，先跑一次随仓库走的只读门禁：

```
node scripts/check-real-host-log.mjs <取回的目录>
```

它判六件事：apply 事件是否都带 `entry`、同一 `runId` 是否只对应一个入口、`entry` 取值是否合法、gate 之后那四条是否出现、两轨 `runId` 能否 join、字段值有没有被写成字符串 `"undefined"`。退出码 0 = 全过 / 1 = 有判据不过 / 2 = 用法或环境错误。**C5（两轨 join）在今天的真实样本上按设计必红**，别把它读成日志丢失；其余五条必须全过。

## 本包的第一次执行：只做到哪一步（诚实区）

- **程序本身**：已落盘（就是本文件），下一次验收直接照做。
- **材料**：已备好生成方式（上表），真机日志由指挥会话提供。
- **自证（非盲）**：本包执行会话按四问逐条走了一遍读法，四问都能只靠读法里的规则答出，
  引用分别落在 Q1 / Q2 / Q3 / Q7 / Q8 / Q10；这一遍**不是盲读** —— 写读法的人自己读，
  只能证明「规则自洽」，不能证明「别人读得懂」。
- **未完成**：真·盲读没有发生。执行会话的委派深度被封死（`subagent` 返回
  `depth 2 exceeds maxDepth 1`），起不了干净上下文的读者。这一条不许写成「已验收」——
  它要一个顶层会话来跑，跑完把表填进 `.tmp-review/`。

## 反例库（用来校准判分，别拿它当答案）

| 现象 | 判 | 为什么 |
| --- | --- | --- |
| 答「没卡」但引的是「末行是 `apply.end`」 | **不通过** | 路径错：那条规则会把正常的轮判成中断（D1） |
| 答「没卡」引的是「`sealed=true` 是结束标记」 | 通过 | 路径对，且判据与位置无关 |
| 答「审计轨 0 行 = 丢日志」 | **不通过** | 没读「五个入口不写审计」这条边界 |
| 答「生效了」但没提 `startup.ready` | **不通过** | 只有 `pendingRestart` 是半个判据，另半个是启动事件 |
| 答「日志里没有这个信息」并且说清缺哪一档 | 通过 | 这是读法要求的行为，不是弃权 |
