# 约束索引

> 一句话：编号即定义：每条约束一句话加它的判定载体。

代码和测试里的注释会引用这里的编号。**编号即定义** —— 看到 `SURFACE-2` 就知道它约束什么，不需要打开别的文档。

表格是索引不是手册：`约束` 列一句话说死规则，`载体` 列指明违反时谁报红。细节在测试里 —— 测试失败信息就是这条约束的说明书。

---

## 编号规则

`<领域>-<序号>`，全大写，不带子字母。领域：`SURFACE` 宿主面 · `TERM` 术语 · `PATCH` 补丁表 · `ARCH` 模块边界 · `DELETE` 删除工程 · `CONTRACT` 对外契约 · `UPDATE` 更新通道 · `AUDIT` 审计 · `READER` 读侧跟随 · `CI` 流水线 · `PERF` 诊断入口性能 · `WORKFLOW` 改动推进方式 · `REPO` 仓库字节与行尾卫生。

**没有「阶段」编号**。`S0`/`A1-A4`/`B1-B3` 那类是执行顺序，不是约束 —— 执行完了就没有意义，留在注释里只会让读者去找一个不存在的东西。

## 风险地图

**当前没有自动化覆盖**的地方。改到相关代码时多留一分心 —— 这些缺口不会有人拦你。

| 缺口 | 情况 | 为什么没做 |
| --- | --- | --- |
| 桌面端冒烟 | 「启动 → 点面板 → 应用 → 重启 → 卸载」只能手工验 | 需要真实 Electron 宿主，`node:test` 跑不了。这是全项目唯一没有自动化兜底的链路 |
| 补丁对宿主源码的匹配 | 每条补丁的 pattern 是否真能在真实宿主文件里命中，没有端到端验证 | 需要真实宿主安装树。`test/patch-three-state.test.mjs` 验的是判定逻辑，不是每条补丁在真实文件上的命中 |
| `lib/redteam/` 零行为覆盖 | 整个演练台（56 个 `redteam_*` 工具 + SQLite 事实库 + 计分规则 + HTTP 桥）没有任何测试验证**行为**。`exports-contract.test.mjs` 只断言 index/store/ui 三个入口能加载、导出数在区间内；tools.js 连加载都要宿主，只断言「失败原因是缺宿主」。算分、存取、工具参数校验一条都没测 | 需要造脱敏靶标夹具 + 临时 SQLite 库 + 宿主工具桩。`arch`（无环）/ `dead`（knip）/ `check:artifact` 全是静态门禁，抓不到逻辑错。这是仓库最大的一块无人区 |
| knip 放过 `lib/client-src/**` | 真死掉的 client-src 文件不会被 knip 报出 | 它们由 build-client 文本装配，静态图上必然零 import 者。替代门禁是 `client-bundle.test.mjs` 的三条互锁断言（orphan 文件会红） |
| knip 盲区：探针脚本动态 `import()` 的模块 | `scripts/probe-host-patches.mjs` 与 `scripts/check-clean-host-sim.mjs` 动态 `import("../lib/core.js")`，knip 把动态导入的模块判为不透明、全部导出视为已引用。实测盲区三文件：`lib/core.js`、`lib/desktop.js`、`lib/atomic-fs.js`（注入未用导出不红；`lib/host.js` / `lib/update.js` 等对照组照红，2026-10-24 HEAD 实测）。测试文件不在 knip 图内，不是根因（ADR 0001 原归因已更正） | 候选修法逐一否掉：静态 import 不治根因且冷路径要动态导入、上游 issue 短期无解、文本死导出检查误报面大且要养白名单、改 `index.js` 命名空间导入不值。已拍板接受残余风险，三文件具名靠评审兜底；取舍见 `docs/decisions/0008-knip盲区重议.md` |
| `gatherState` 的真实变慢 | 墙钟断言降级成信息项之后，「从 1.5 s 抬到 6 s」这种整体变慢**今天没有任何自动化载体**：判据只剩「不挂死」的结构阈值与打印出来的采样值，而采样值在并发套件里噪声大到分不出真退化（实测过改前 8 轮红 2 的假红，也就会掩盖同量级的真红） | 需要的是一条与负载无关的度量（如 IO/调用次数、或隔离到独占运行的单进程基准），本机与 CI 都还没有。`PERF-1` 的文本已按现状改写（结构性判据 + 挂死上限），别再把它读成性能预算 |
| 密封 CLI 的版本账本门槛比面板松一档 | `ensureHostClean` 不返回 `hookDenyRestoreFailed`；`flash.ok` 也不进 CLI 的 `isCleanApplyRound`。密封路径靠 `cleaned.ok`（待清洗项 / 硬失败 / flash / 标记未写全）挡，剩下「安全阀还原失败但其余三档都过」那一档会写进账本，而面板那条路不会 | 逐字同义要给 `ensureHostClean` 的返回补字段，那是 `lib/core.js` 的引擎冻结面；口径已由 `AUDIT-4` 与 `docs/decisions/0014-版本账本成功口径.md` 定下，要不要修另开条目（账本 E10） |
