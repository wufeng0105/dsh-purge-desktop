# 文档索引

> 一句话：每份文档回答什么问题，以及哪些内容不该写成文档。

本仓库的文档按「读者要拿它做什么」分三类。**新建文档前先在这里的索引表登记**，避免同一件事写两遍、或者写在没有人的地方。索引表是 `scripts/check-layout.mjs` 的输入：`docs/` 下每个 `.md` 必须在这里出现**恰好一次**且带一句话，登记了但文件不存在同样报红。

## 说明型 — 给使用者

读者拿到这个仓库，想知道「这是什么、怎么装、怎么用」。

- `README.md` —— 是什么、装在哪、三步上手、面板各页做什么、路径探测、还原与更新。不写设计理由、不写补丁 id、不写测试怎么跑。
- `README.en.md` —— 同上，英文。
- `release-notes.md` —— 当前版本的变更说明，中英双语。1.1.x 的历史看 git log。

**判据**：如果一段话对「只想把它装上用起来」的人是噪音，它就不该在说明型文档里。

## 技术型 — 给维护者

读者要改这个仓库，需要知道「为什么这样设计、约束是什么」。

- `AGENTS.md` —— 给 AI 协作者的仓库导航：只写**读仓库读不出来的事实**与**不写就会做错的动作**（三份产物的区分、大文件先符号后片段、`test/` 发现规则、生成链、门禁集合、注释规范）。不写业务规则、不抄目录清单与命令表。
- `docs/约束索引.md` —— 每条约束的编号、一句话内容、对应的测试或配置载体；风险地图。不写安装步骤、不写版本变更史。
- `docs/布局约定.md` —— 目录职责、豁免表、命名约定、判不了的整洁要求。它是两条整洁门禁的输入。
- `docs/状态层契约.md` —— 五块状态（补丁 / 审计 / 技能 / 环境 / 预设）加 health 块的字段、唯一生产者、派生方式与副本数；消费者清单。字段声明以 `lib/state/contract.js` 的 `STATE_BLOCKS` 为准，这两处由用例逐行比对。
- `docs/dsh-native-primer.md` —— 宿主的插件生命周期、座位模型、客户端加载链、服务与配置、主题样式的入门；每条结论附宿主仓库路径行号。
- `docs/readme-for-ai.md` —— 给没读过本仓库的 AI 的日志读法：两条 JSONL 轨的落点与字段、一次 apply 该按什么顺序出现哪些事件、`runId` 怎么 join、九个 `entry` 各是谁、判「卡住」的症状→字段→下一步命令。不写设计理由、不抄字段规范表。
- `docs/decisions/` —— 架构决策记录（MADR 格式）：门禁与工具链取舍的历史留痕，每篇含背景、决策、后果三段。与约束索引的分工写死：索引说「现在的规则是什么」，decisions 说「当时为什么这么选」；改规则先改索引，取舍变了再补一篇。
- `docs/rebuild/**` —— 已整组退役：M0 期的现状清单、目标设计、迁移计划、评审简报、审计日志设计与宿主能力实测都在里面，2026-10-27 起整份删除。那一轮的事实与取舍只能从 git 历史取回（`git log -- docs/rebuild/`）；现状以源码与门禁为准。
- `docs/界面重构计划.md` —— 界面重构计划：设计系统、两阶段执行与验收判据。

**判据**：如果一段话的价值在于「防止未来某次改动犯错」，它属于技术型。

**唯一权威**：约束的编号与内容以 `docs/约束索引.md` 为准。代码注释里引用编号时，指向那里。「之前是什么状态、改了什么」这类历史叙述不留在技术型文档里 —— 那是 git 历史的职责。

## 素材型 — 被引用，不能随意动

| 路径 | 被谁引用 | 约束 |
| --- | --- | --- |
| `docs/preview/*.png` | `screenshots.json` → `lib/update.js` 的 `COPY_NAMES` | 改文件名要同步改 `screenshots.json` |
| `docs/banner.svg` | `README.md` / `README.en.md` 顶部 | 改名要同步改两份 README |
| `docs/drill-auth-legal.html` | `lib/client-src/dock/auth-gate.js`（逐字节内联为 `AUTH_LEGAL_HTML`）+ `test/client-evaluates.test.mjs` | **改内容必须同步改 `auth-gate.js` 并重跑 `npm run build:client`**，否则 drift 门禁会红 |
| `docs/redteam-upstream-LICENSE` | `README.md` / `README.en.md` 的第三方声明 | 许可证文本，不许改内容 |
| `docs/redteam-upstream-DISCLOSURE` | 同上 | 同上 |

**判据**：素材型文档的「正确性」由引用方定义，不由内容本身定义。

**外部权威**：《突破入侵类得分规则（合并版）》不在本仓库内，也从未在 git 历史里存在过。仓库内现行口径以 `lib/redteam/score-rules.js` 的 `DEFAULT_SCORE_POINTS` 为唯一实现；需要 G1–G8 逐条正文时用 `git show 0b24dfb:lib/redteam/score-rules.js` 从 git 历史取，**不要再抄回 `lib/`**。

## 不该在这里的东西

| 内容 | 该放哪 |
| --- | --- |
| 补丁表本身 | `lib/patch/table.js` 的 `ALL_PATCHES` —— 代码即文档，`docs/约束索引.md` 只登记结构性约束 |
| 版本号 | `package.json` 的 `version` + `release-notes.md` 首行，两处必须一致 |
| 宿主版本要求 | `package.json` 的 `dshTarget`，门禁在 `lib/host-version.js` |
| 测试怎么跑 | `package.json` 的 `scripts`，`docs/约束索引.md` 每行标了对应载体 |
| 某次改动的过程台账 / 验收报告 | git log 与 git tag。过程性文档不入库——正文只会在下一次改动后变成假话，2026-10-24 起 `docs/rebuild/archive/` 已退役 |
| 临时产物（`.tmp-*`、一次性脚本、`*.tgz`） | `.gitignore` 已覆盖，不进仓库 |
