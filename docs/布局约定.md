# 布局约定

> 一句话：每个目录放什么、哪些文件允许超限、名字怎么起。

这份文档有两个读者：要放新文件的人，和 `scripts/check-layout.mjs`、`scripts/check-file-roles.mjs` 两个门禁。**能判的整洁要求都已经在门禁里**，这里只写门禁读得懂的表，加上第四节判不了的那部分。改表就是改门禁，改完跑一遍两条命令。

---

## 一、目录职责表

一行一个目录，一句话说职责，紧跟允许的文件名模式。**模式里没有斜杠的按任意深度匹配** —— `lib` 的 `*.js` 覆盖 `lib/` 下所有层级，所以表的行数等于目录数，而不是等于每个子目录一行。表外目录里的文件、表内目录里不匹配任何模式的文件，都报红。

| 目录 | 允许的文件名模式 | 一句话职责 |
| --- | --- | --- |
| `lib` | `*.js`, `*.mjs`, `default-prompt-inject*.md`, `*.wscript` | 插件运行期代码（宿主侧 Node 模块），一个文件一件事 |
| `lib/client-src` | `*.js` | 片段：被 `build-client.mjs` 文本装配进 `client.js` 的正文，不是模块 |
| `lib/redteam` | `*.js` | 演练台：资产库、计分规则、工具集、HTTP 桥与浏览器半侧 |
| `lib/audit` | `*.js` | 审计日志：事件形状、三层口径、JSONL 存储与落账报告 |
| `lib/host` | `*.js` | 宿主侧事实：安装路径、补丁目标表、启动 apply、shim 写回 |
| `lib/patch` | `*.js` | 补丁数据与字面量常量（`table.js` 受 `REPO-1` 行尾冻结） |
| `lib/prompt` | `*.js` | 宿主提示词文本清洗（YAML / persona 标量） |
| `lib/shim` | `*.js` | CLI shim 的静默目标表与单执行器 |
| `scripts` | `*.mjs`, `*.sh` | 仓库侧命令：生成链、门禁、度量、只读探针 |
| `test` | `*.test.mjs`, `helpers/*.mjs`, `fixtures/**` | 单元与契约测试；`npm test` 递归执行本目录全部 `.js` / `.mjs` |
| `bin` | `*.js` | CLI 入口（`dsh-purge` 命令本体） |
| `architecture` | `*.yaml`, `*.json`, `README.md` | 冻结的架构产物与机器可读数据；生成器已退役，不许手改成结论 |
| `docs` | `*.md`, `*.svg`, `*.html`, `*.json`, `redteam-upstream-*` | 给人读的文档与素材，按读者分三类；`*.json` 只放**读法要引用的机器可读表**（如 `log-generations.json`），不放导出数据 |
| `docs/decisions` | `*.md` | 架构决策记录（MADR）：历史取舍的留痕，现行规则仍在约束索引 |
| `docs/preview` | `*.png` | README 截图，文件名被 `screenshots.json` 引用 |
| `.github` | `workflows/*.yml` | CI 与发布流水线 |
| `rules` | `*.yml` | ast-grep 规则，`patch-guard` 的输入 |
| `presets` | `*.yml`, `*.mjs` | 随插件交付的 agent 预设 |
| `skills` | `*.md` | 随插件交付的红队技能说明 |
| `preview` | `fixtures/*.json` | 真机采样的只读夹具 |

**为什么没有根目录一行**：根目录只放包元数据（`package.json`、`tsconfig*`、`README*`、`LICENSE`）与点文件（`.gitignore`、`.npmignore`、`.gitattributes`、`.dependency-cruiser.mjs`），它们的正确性由 `npm run verify` 的导出契约与文档门禁守，不由目录表守。第二节的禁用名对根目录同样生效。

## 二、豁免表

单文件不超过 800 行。越过的必须在这里登记，类别只许三种，且**每一行都要写清「为什么不能切」** —— 写不出来就不是豁免，是该切的债。

| 文件 | 类别 | 为什么不能切 |
| --- | --- | --- |
| `lib/patch/table.js` | 纯数据表 | 66 条活跃补丁的替换正文字面量本身就是数据，行数即数据量；且该文件受 `REPO-1` 整文件行尾冻结，切开会让「逐字节未改」这条判据失去对象 |
| `lib/client-src/i18n.js` | 纯数据表 | zh / en 两份词典逐键对齐，它的全部价值就是两条键序能一眼比对；切成两个文件等于把比对搬到读者脑内 |
| `lib/redteam/client.js` | 已排期拆分 | 排到第 2 轮：演练台按域拆分，切分要跟着宿主席位一起验，本轮不动 |
| `lib/redteam/store-core.js` | 已排期拆分 | 排到第 2 轮：前置是给 SQLite 事实库补行为快照；零覆盖下切 5400 行无法证明行为不变 |
| `lib/redteam/tools.js` | 已排期拆分 | 排到第 2 轮：按「参数 schema / 执行体」二分，前置同上一条 |
| `lib/redteam/ui.js` | 已排期拆分 | 排到第 3 轮：HTTP 桥与设置页逻辑分离，前置是演练台浏览器半侧先拆完 |
| `lib/core.js` | 已排期拆分 | 排到第 3 轮：补丁引擎与宿主交接分离，前置是把 `patch-characterization` 快照扩到宿主侧 |
| `lib/index.js` | 已排期拆分 | 排到第 4 轮：导出聚合层切分要同步 `exports-contract` 用例冻结的 5 个具名导出（`apply`、`default`、`inject`、`name`、`registerPromptSections`）。`CONTRACT-1` 的 7 条是 `package.json` 的**整包** exports 键数，不是这一个文件的导出面，别混 |
| `lib/desktop.js` | 已排期拆分 | 排到第 4 轮：安装定位与重启计划分离，前置是真机验证（本机跑不了 Electron） |
| `lib/update.js` | 已排期拆分 | 排到第 4 轮：更新通道与版本比较分离，前置是 `update-channel` 用例覆盖出网守卫全部分支 |
| `lib/host/paths.js` | 已排期拆分 | 排到第 5 轮：路径探测与 memo / pathZone 判定分离，前置是先固化一份探测结果快照 |
| `scripts/probe-host-patches.mjs` | 已排期拆分 | 排到第 2 轮：1294 行里一半是逐条宿主文件的判读规则，切分只能靠真机复核，本机跑不了 Electron |

**死账也报红**：登记了豁免但文件已不存在、或已经降到 800 行以内，`check-file-roles.mjs` 会点名。豁免表是账本，不许留过期行。

## 三、命名约定

### 禁止的后缀与名字

| 模式 | 说明 |
| --- | --- |
| `.bak` | 备份只许落在运行期的 `host-backups`，不许进仓库 |
| `.old` | 同上 |
| `.copy` | 同上 |
| `-2` | 同目录重名靠改名解决，不靠加数字后缀。只查代码与数据文件（`.js` / `.mjs` / `.json` / `.txt` / `.yml` / `.yaml` / `.md`），素材图有自己的语义名 |
| `tmp-*` | 临时产物不进仓库，`.gitignore` 已覆盖 |
| `tmp_*` | 同上 |
| `.tmp-*` | 同上（点开头的临时文件同样算） |
| `.tmp_*` | 同上 |
| `*.tgz` | 打包产物不进仓库，发版由 tag 触发 |
| `utils.js` | 这类名字不说明职责，谁都能往里塞。依赖侧由 `no-catch-all-filenames` 拦引用，这里拦存在 —— 两条一起才拦得住「塞到第三处」 |
| `helpers.js` | 同上 |
| `common.js` | 同上 |
| `shared.js` | 同上 |
| `misc.js` | 同上 |

**匹配方式**：带 `*` 的按前缀 / 后缀匹配，不带 `*` 的按**完整文件名**精确匹配（`utils.js` 只拦同名文件，`ip-utils.js` 这种带业务前缀的不算）。

### 同类文件同前缀同目录

| 前缀 | 目录 | 说明 |
| --- | --- | --- |
| `check-` | `scripts` | 门禁一律叫 `check-<判什么>.mjs`，入口只有一条命令 |
| `patch-` | `lib/patch` | 补丁数据与常量只在这个目录 |
| `policy-` | `lib/client-src/settings` | 策略分节片段按「全局 / 单点」分文件，前缀固定 |

**前缀规则的作用域**：只查 `lib/`（不含被文本装配的 `lib/client-src/`）与 `scripts/`。`test/` 按 `*.test.mjs` 命名、`rules/` 按 `*.yml` 命名，各有自己的约定，不受本表约束 —— 否则 `test/patch-characterization.test.mjs` 会因为名字里有 `patch-` 被误判到 `lib/patch/`。

**为什么前缀值得管**：名字是唯一一项不读内容就能判断「这东西该在哪」的线索。`check-*` 跑出 `scripts/` 就说明有人把门禁写成了运行期依赖；`policy-*` 跑出设置页片段目录就说明有人把界面逻辑塞进了服务端。

## 四、判不了的整洁要求

能按命令判的都在两个脚本里了。剩下三条判不了，写在这里，靠评审：

**一、这一句话是不是「为什么存在」而不是「里面有什么」。** 门禁只能判有没有那一行、多少字、有没有并列连词。`lib/table-key.js — 密封槽。` 与 `lib/table-key.js — 密钥由机器指纹派生，所以跨机复制的密封槽解不开。` 都过门禁，只有后者回答「为什么存在」。判断这句话是否说清了存在理由，需要读懂文件在调用链上的位置 —— 这是评审的活。

**二、切分是不是切在了接缝上。** 门禁能判行数、能判被移动的行逐字相同，判不了「这条接缝是不是真接缝」。把 800 行按 400/400 劈开同样能过全部检查，但会让两个文件都说不清自己的一件事。

**三、依赖方向是不是真的反映了职责方向。** `dependency-cruiser` 只能判「这条边不许存在」。「这条边存在但方向是不是最优」「有没有为了绕规则把东西塞到第三处」需要人看架构图 —— 文件黑名单只能拦住最蠢的那种塞法。
