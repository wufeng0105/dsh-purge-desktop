# 界面重构计划

> 一句话：界面重构计划：设计系统、两阶段执行与验收判据

## 0 依据与范围

- 基线：`HEAD f88d166`、`package.json` 2.3.2（2026-10-27 当轮取值）。行号一律按文件内容复算，不按键对行；动了状态契约或界面源码就回改这一句 —— 写死一个会走的 hash 而不说明「按内容复算」，下一次提交就把它变成假话。
- 范围：设置页（宿主 `settings.section` 里 dsh-purge 一节）+ 演练台（`main` 座位整页）的界面。
- 两个名字别混（同一处的两种口径）：宿主 `settings.section` 的**注册 id 是 `dsh-purge`**；界面左栏**显示名取 `lib/client-src/i18n.js:14` 的 `nav` 键**，中文是「规则设定」（英文 `Rules`）。发版前人工门按**注册 id** 写（`AGENTS.md` 里那句「设置左栏多出 `dsh-purge` 一节」维持原样、不改），界面文案按 `nav` 键走；照字面在左栏找 `dsh-purge` 四个字的测试员会误判一条本来通过的链路。
- 已拍板（2026-10-27）：**5 页签**划分接受；**演练台与设置页是同一个重构项目**，分两段顺序执行——阶段一先交付设置页，阶段二交付演练台，不属于另行排期。
- 评审阶段的参考稿（原型 HTML，不入库，已随临时产物清理删除）只作为视觉语言与交互规范参考；**外壳（三栏布局）不采纳**，理由见 §2 D1。
- 本计划是审计对象：每条决策给证据、每个组件给状态、每块页面给真实接口与验收判据。

## 2 架构决策

### D1 座位与信息架构

- 设置页继续留在 `settings.section`，演练台继续留在 `main`。**不改座位**，不触碰 `architecture/ui-tree.yaml` 与 ADR 0015。
- 设置页改为**单列 + 5 页签**：`状态` / `补丁` / `配置` / `技能` / `诊断`。危险操作放「配置」末尾，用分隔线隔开。
- **删除页内 10 项锚点导航**；不使用第二左栏、右栏、1240px 白纸容器。内容宽度由容器决定，最大 `760px`。
- 移除 `shell.js:261` 从未消费的 `children: { "settings.dsh-purge.tab": … }` 声明（死能力；页签由本页自己渲染）。座位注册形状其余不变。

理由：宿主 `settings.section` 是设置页里的一栏，不是整窗。参考稿断点按视口算、`sticky top:0` / `100vh` 假定自己拥有视口，在设置节里会错位。宿主自己的复杂界面（plugin-manager）住在 `main`、设置里只留窄节——按同一分工走。

### D2 设计系统

- **一个令牌命名空间** `--dshp-*`，两层：
  1. 基础层（数值）：间距、字号、字重、行高、圆角、边框、阴影、层级、动效、控件尺寸、内容宽度。
  2. 语义色层：全部 `var(--dsw-alias-…, 兜底)`；明暗归宿主，**不出现** `[data-theme]` / `.dark` / `prefers-color-scheme`。
- **一个类名前缀** `dshp-`。`.rt-*` 作为演练台遗留前缀保留到阶段二，届时只改取值不改成批类名（约 4400 行，本版不拆，见 §6.6）。
- CSS 拆 3 个片段：`design/tokens.js`、`design/components.js`、`design/layout.js`；`dock/purge-css.js` 改拼接入口。每份 < 300 行（800 行上限由 `scripts/check-file-roles.mjs` 兜底）。新增占位符同步登记 `scripts/build-client.mjs` 的 `SLOT_FILES`，保持 `client-bundle.test.mjs` 的"占位符有源、源被引用"。

### D3 原生 vs 自建

能力探测后移到最终终验（§9）；探测出结论之前按本表默认值实现，适配层保证任一原生缺失都能降级。

| 组件 | 决策 | 理由 |
| --- | --- | --- |
| Button | 原生优先，外包 `danger` 变体 | 宿主无 danger；`ActionButton` 已有降级先例 |
| Switch | 原生 | 已用，带原生键位与焦点环 |
| StateDot | 原生 | 状态词映射 done/error/idle |
| 图标 | 原生优先（`Icon*`），缺失用内置 SVG 集 | 不引外部字体/图标库 |
| Field / Input / Textarea / Select | 自建 | 有服务端错误、草稿保留、加载态；`SettingsValueField` 行为未证实 |
| Tabs | 原生有则用，无则自建 | 需要 `role=tablist` + 方向键 |
| Modal / Dialog | 原生有则用，无则自建 | 卸载走二次确认弹窗，原生行为未证实 |
| Toast | 原生有则用，无则自建 | 需要成功/失败/警告三态 |
| 表格 | 自建 | 宿主无数据表原语；需窄档卡片化 |
| `SettingsForm` | 不用 | "保存失败保留输入"等行为在 primitives 内不可见；我们的表单是异步端点 + 服务端错误 |

### D4 数据与状态

- 一个页级 `usePurgeStatus`：`GET /dsh-purge/status` 只请求一次，页签从同一份快照读；POST 成功后 `refresh()`。
- 各页签自己的只读端点**在页签挂载时取一次**，统一走 `useAsyncResource`（loading / ready / empty / error / retry），不再各写一套 `busy/notice`。
- **计数只在服务端算**（`settings-readonly-blocks` 已有判据）：`layerRows` 整串交给渲染；技能计数读 `/dsh-purge/skills` 的 `total/byLibrary/shadowed`；补丁计数读顶层 `patches_*`。
- **两种分母必须标名**：摘要与补丁页使用 `display` 口径（62 行）并注明「按展示行」；`raw`（66）只出现在诊断页「判据口径」行。不允许只报数字。
- **只用契约字段**：不显示 `lastApplied`（契约没有；`applied_at` 已被明确移除）；最近一轮只显示 `audit.appliedRunId`。
- **不恢复"应用"按钮**：2.0.0 起界面无此按钮，手动重放走 `/purge apply`。
- 状态点/色调只由服务端 `tone` 决定，客户端不映射 status→颜色。

### D5 框架与构建

- **不引入任何运行时框架**：React 来自宿主冻结模块表，零体积；自带 React 副本会造成 hooks/context 分裂；Preact/Vue/Svelte 丢 slots/inject 整合。**不引组件库 / Tailwind / 原子 CSS**（第二套主题、全局 preflight、体积）。
- **不引入 JSX 构建**：`h()` 虽啰嗦，但加 esbuild 会改生成链（逐字节幂等、CI drift、knip/tsc/ast-grep、`SLOT_FILES` 接受 `.jsx`），且不解决任何设计问题。若确需，另开 ADR。

### 3.3 间距 / 圆角 / 边框 / 阴影 / 层级 / 动效

- 间距：**沿用磁盘现存族** `--dshp-sp-1..6` = 4 / 8 / 12 / 16 / 20 / 32（`purge-css.js:354` 定义 6 档，全仓 32 处命中 = 6 处定义 + 26 处引用）。新增档从 7 起：`--dshp-sp-7:40`、`--dshp-sp-8:48`、`--dshp-sp-9:64`，继续 4px 节奏。**`--dshp-sp-6` 保持 32 不改**：它已有 26 处引用，改成 24 要逐处复验视觉，而这条没有自动化能拦。原先那套以 `space` 拼前缀的间距族全仓 0 命中，是计划自造的名字，删掉。
- 圆角：`--dshp-radius-xs/sm/md/lg/full` = 4 / 6 / 8 / 12 / 999；宿主 `--dsw-radius-*` 存在时覆盖。
- 边框：`--dshp-border-w: 1px`、`--dshp-hairline: .5px`；`--dshp-border: var(--dshp-border-w) solid var(--dshp-color-border)`。
- 阴影：只有 `--dshp-shadow-overlay`（浮层）与 `--dshp-shadow-toast`；页面与卡片无阴影。
- 层级：**走设计级，不比宿主数字**。`.dshp-root` 与每个浮层根各自 `isolation:isolate` 建一层隔离的层叠上下文，层内 `z-index` 只与插件内部的值互比，取值大小不再有全局含义；与宿主之间只在**边界那一个元素**上留一个数字，边界值单列命名并写明它为什么是那个数。判据是**裸 `z-index` 零容忍**：`z-index` 在 `check-design-tokens` 的裸值属性表里，写成数字即命中，层内一律走 `--dshp-z-*`。原先那条「令牌取值必须高于 rewind 菜单的 2147483000」按本决策作废——隔离层之后，压过宿主弹层不再是插件内部取值的职责。盘上今天的裸值如实留在这里（`layout.js` 的 `10050` / `10040`、`components.js` 的 `80` / `10100` / `10200` / `12000`、`rewind-ui.js` 的 `2147483000`），收编只换写法、不改视觉；层叠上下文与这批取值同一条执行批落地，不由本文档代劳。
- 动效：`--dshp-dur-fast:120ms`、`--dshp-dur-base:180ms`、`--dshp-dur-slow:240ms`；`--dshp-ease: cubic-bezier(.2,.8,.2,1)`；`prefers-reduced-motion` 全部降到 1ms。
- 控件：`--dshp-control-sm/md/lg` = 28 / 34 / 40；`--dshp-touch-min:44`；焦点环 `--dshp-focus-ring: 2px` + offset 2。
- 内容宽度：`--dshp-measure: 68ch`；设置页 `--dshp-content-max: 760px`；演练台 1100px（不变）。

### 3.4 字面量例外（写进门禁）

允许：`0`、`auto`、`100%`、`fr`、`minmax()`、`calc()` 内仅令牌、`inherit`、`none`、`currentColor`、`transparent`；容器/媒体查询断点（CSS 语法限制）；`1px` 只能由 `--dshp-border-w` 表达。其余 `margin / padding / gap / font-size / font-weight / line-height / border-radius / box-shadow / z-index / transition-duration / animation-duration / color / background` 的裸数值一律判红。

## 4 布局规范

### 4.1 设置页

```
[页面头]  dsh-purge v2.3.2   状态词             [重启（仅在需要时）]
[页签]    状态 | 补丁 | 配置 | 技能 | 诊断
[内容]    单列，max-width 760，分组间距 sp-6，组内行间距 0（发丝线）
```

- 页面标题一次（`fs-page`）；分组标题 `fs-section/600`；行标签 `fs-sm/500`；说明 `fs-meta`。
- 行：`grid-template-columns: minmax(0,auto) minmax(0,1fr) auto`；不设固定标签宽度。
- 危险区：与上方隔 `sp-6` + 一条 hairline，不另造容器。
- 页脚：日志 / 配置文件两个文字按钮 + `dsh_home`（等宽）。

### 4.2 响应式（容器查询，不按视口）

页面根设 `container-type: inline-size`，三档：

| 档位 | 容器宽度 | 行为 |
| --- | --- | --- |
| compact | < 520px | 页签横向滚动；行「标签在上、值在下」；按钮全宽；表格转卡片 |
| narrow | 520–840px | 页签可换行；行保持左右；表格自身横向滚动 |
| wide | > 840px | 单列 760 居中；页签一行 |

兜底：宿主 Chromium 不支持容器查询时，用 `ResizeObserver` 在根节点写 `data-dshp-width`。二选一（容器查询 / ResizeObserver 主用哪条）**在最终终验现场定**（§9）；定下来之前两套都留：适配层写 `data-dshp-width`，CSS 的 `@media (max-width:900px)` 兜底同时存在，删哪一套等终验给出宿主版本再决定。

### 4.3 演练台

- 保持 1100px 内容列与页头 / 标签栏 / 正文三段结构，不改 IA。
- 阶段二把 `@media` 断点统一到 900 / 1100，`.rt-*` 消费 `--dshp-*` 令牌。
- 表格行高 32 / 表头 36、数字列右对齐等宽，保持 `design-baseline` 现有断言。

### 4.4 溢出与长内容

- 所有 flex/grid 子项 `min-width:0`；长路径 / runId `overflow-wrap:anywhere`；表格单元格 `text-overflow:ellipsis` + `title`。
- 页面级不得出现横向滚动条；窄档表格允许自身横向滚动。
- 目标测试宽度：320 / 520 / 760 / 900 / 1280 / 1440。这六个宽度今天在仓库里没有载体，判据落在最终终验的截图清单里（§9），阶段一与阶段二不挂它们。

## 6 页面规格（对齐真实接口）

### 6.1 状态

- 数据：`GET /dsh-purge/status`（一次）。
- 字段：`patches_applied/pending/skipped/failed/na/total`、`boot_full_quit`、`shim_cmd/ps1/bin`、`has_backup`、`preset`、`env`、`plugin_version`、`surface`、`dsh_home`。
- 内容：结论句（四种数；pending > 0 绝不说"全部生效"）；四个计数（标 `display` 口径）；运行环境三行（命令入口 / 备份 / 预设，人话）；需要时「重启宿主」。
- 态：加载骨架；宿主未定位（`ai_base` 空）给可操作说明；读取失败整页 ErrorBlock + 重试。
- 动作：重启（二次确认，文案说明"正在编辑的设置不会保存"）。

### 6.2 补丁

- 数据：同一份 status 的 `layerRows`（`layer/slug/title/hit/total/skipped/pending/tone/items[]`；`items` 含 `id/name/desc/tone/bucket/reason/error`）。
- 内容：总体计数（display 口径 + 注明）、按层展开（服务端已过滤空层，客户端不再分组）、每条状态点 + 名称 + 原因。
- 不做：客户端 `filter/reduce/length` 再计数（`settings-readonly-blocks` 判据）。

### 6.3 配置

| 子块 | 接口 | 字段 / 动作 | 态 |
| --- | --- | --- | --- |
| 更新 | `GET /dsh-purge/update` | `updateDisabled/Reason`、`localVersion`、`channel`、`hasUpdate`、`remoteVersion` | 本地版不画按钮，只写原因 |
| 提示词注入 | `GET/POST /dsh-purge/override` | `content`、`defaultContent`、`customized`、`usingDefault`、`path`、`system_field_extracted`；保存失败保留草稿 | 加载 / 保存中 / 失败 |
| 服务器名单 | `GET/POST /dsh-purge/own-servers` | `content`、`dropped` | 保存后提示丢弃条数 |
| Hooks 拦截 | `GET/POST /dsh-purge/hooks-deny` | `hooksDenyBypass` | 开关即时保存，失败回滚 |
| 危险操作 | `POST /dsh-purge/revert`、`POST /dsh-purge/uninstall` | 不可撤销；卸载走二次确认弹窗（取消 / 确认卸载两个按钮，无勾选框） | 确认弹窗 + 结果 toast |

### 6.4 技能

- 数据：`POST /dsh-purge/skills?op=status`（兼容 `/skill`）→ `skills_dir`、`skills[]`、`total`、`byLibrary`、`shadowed`。
- 动作：`read` / `save` / `delete` / `import`（zip / 文件夹）。
- 内容：来源筛选（全部 / 官方 / 红队 / 本地导入），计数只用 `byLibrary`；随包副本只读；编辑器在该行下就地展开。
- 空态：无技能 / 筛选无结果 两句话分开。

### 6.5 诊断

- 审计：`GET /dsh-purge/audit?tail=20`（`events[]`）、`?check`（`ok/files/gaps/badLines`）、`?run=<runId>`（`found/audit[]/diag.rows/cards[]/cross{matched,checked,comparable}`）、`?seq=<n>`（证据链）。只读。
- 健康：`GET /dsh-purge/health` → `install{recorded,version,method,at,files,drifted,missing,added,consistent}`、`presetCopy{present,files,drifted,consistent}`。
- 日志：同一响应的 `logs{audit{path,present},diag{path,present,generations,maxBytes},internal{…}}`；三条轨合成页脚一行，保留代数作为注解。
- 口径行：展示 `counts.raw` / `counts.display` 两种分母的说明（只读文本，不重算）。
- 态：无记录 ≠ 一致（三态：未记录 / 一致 / 不一致）。

### 6.6 演练台（阶段二）

10 个页签保持不变：资产、环境、智能体、会话、发现、链路、计分、报告、知识库、技能。数据继续走 `POST /redteam/api`；阶段二只做令牌与件级视觉统一，不改座位、不改 op、不改页面结构。

**「不改 op」的可复算口径**（WP1 执行者 2026-10-27 实测，三条都不是抄来的数）：

- 服务端派发：`lib/redteam/**` 里 `op` 与字面量的比较（`==` / `===` / `!=` / `!==` 四种）去重 **80**；只算 `===` 是 79。本计划一直写的「80 个 op」正是这一口径，分母是服务端目录里的比较字面量、不是客户端请求数。
- 客户端请求：`lib/redteam/client.js` 里 `op: '…'` 字面量去重 **44**（客户端只发它真会用到的那些）。
- 全域旁证：`lib/**` 里 `op === '…'` 同为 79（这些比较全写在 redteam 目录内）；把技能端那套双引号 `op` 一起算进来是 96 —— 多出来的是 `/dsh-purge/skills?op=…` 的另一套命名，与演练台无关，不许混计。

阶段二做完这三条数字都不许变；变了就是动了 op 面。

## 7 状态与异步规范

1. 每个数据区显式建模 `loading / ready / empty / error`；未取到就是错误块，不显示上一轮旧数字。
2. 每个异步动作：loading → 禁用触发按钮 → 成功后刷新或就地更新 → 失败显示服务端 `error`（经文案层）→ 永不重复提交。
3. 保存类动作失败保留用户输入（override / own-servers / 技能编辑器）。
4. 删除 / 卸载 / 还原必须二次确认：弹窗只有取消与确认两个按钮。卸载不设勾选框 —— 界面里本来就没有这个控件，判据文本与界面按同一口径写（发版前人工门见 `AGENTS.md`）。
5. 按钮文案是动词短语（保存注入、导入 ZIP、重新读取、执行还原），禁止含糊表达。
6. 工程字段不上屏：`shim` / `binary` / `missing` / `phase` / `broken` 一律经人话函数（保留 `settingsShimWord` / `settingsBackupWord` / `settingsPresetWord`）。

## 8 可访问性规范

- 每个页签一个 `tabpanel`，`aria-labelledby` 指向页签；方向键 / Home / End 切换。
- 焦点：2px 环 + `outline-offset:2px`；浮层打开焦点移入、关闭后归还触发元素；Tab 陷阱。
- 表单：每个控件有 `<label for>`；必填标 `*` 且 `aria-required`；错误 `aria-invalid` + `aria-describedby` + 图标 + 文字。
- 状态：图标 + 文字，选择态不只靠底色；按钮禁用用 `disabled`，加载用 `aria-busy`。
- 图标：装饰性 `aria-hidden="true"`；图标按钮有 `aria-label`。
- 对比度：在最终终验用计算色实测 `text-primary/secondary/tertiary` 与背景（§9）；实测之前按保守值实现——正文一律 secondary 以上，tertiary 只用于非必要元信息。
- 动效：`prefers-reduced-motion` 全禁用；触控目标 ≥ 44px（`pointer: coarse`）。

## 13 交付顺序

1. 阶段一 设置页：令牌层 → 信息架构 → 视觉 / 状态 / 响应式 / 无障碍 → 预览图收尾项；仓库侧判据全绿。
2. 阶段二 演练台：`.rt-*` 消费令牌 → 断言更新 → 重拍演练台那几张图；仓库侧判据全绿。
3. 最终终验：远端测试机装好，用户亲看 GUI，五项人工门 + 六项探测逐条打勾；不过就回改重跑整条链。
4. 收尾：清理遗留件、给 `docs/约束索引.md` 加 `DESIGN` 域并登记约束、更新发布说明 → 发版。
