# 术语账本

> 一句话：全组文档与代码注释共用的唯一写法和主线，改名前先改这里。

这份文件管两件事：**这组文档合起来在主张什么**，以及**同一个东西只能有一个名字**。它不是词典，是账本 —— 每次动笔前重读，改一个名字就回来改一行。名字漂移是读者察觉「这几篇不是一个人写的」的第一信号。

---

## 主线

**把宿主拦截与模型拒绝分开，且每一句结论都能被一条命令复算。**

README 证明「值得装」，AGENTS 证明「改得动」，约束索引证明「改错了会被拦住」，布局约定证明「摆错位置会被拦住」，决策索引证明「每个取舍都有当时的理由」。任何一段话如果不服务这两条中的一条，它就不该在这组文档里。

---

## 账本

一个东西一个名字。「禁用」一列里出现过的写法，改稿时一律换掉。

| 唯一写法 | 含义（一句话） | 禁用的同物异名 |
| --- | --- | --- |
| 补丁 | 改宿主文件的一处替换，带 pattern 与 marker | 清洗项、patch 条目 |
| 补丁表 | `lib/patch/table.js` 那份数据 | 补丁数据、补丁清单、补丁列表 |
| 活跃补丁 | 表里当前生效的那些（66 条） | 有效补丁、在用补丁 |
| 空洞 | 永久保留但不再活跃的 id，`reason` 必填 | 空 id、holes、retired、墓碑 |
| id | 补丁的编号，写作 `id 46` | `#46`、补丁号 |
| 编号 | 约束的编号，写作 `PATCH-1`、`SURFACE-2` | 条款号、章节号 |
| 宿主 | 被改造的 DeepSeek Harness 本体 | 官方端、harness（作名词时） |
| 官方 | 只作形容词：官方原文、官方能力、官方宿主 | 把「官方」当名词指宿主 |
| 装机树 | 本机已装、可能已被改过的宿主树 | 本机树、实机树 |
| 干净宿主 | 密封 `app.asar` 里未清洗的官方原文 | 纯净宿主、原始宿主 |
| 宿主面 | `surface`，现在只有 `desktop` | 平台、端类型 |
| 座位 | 宿主界面上的挂载点（`settings.section` / `main` / `sidebar.panellist` / `conversation.input.right` / `shell.overlay`） | 界面槽位、挂载位、slot |
| 密封槽 | 提示词密文槽（`asset-table.js` 的 `SLOT` / `MASK` / `TAG` / `IV`） | 槽位、加密位、加密槽（不加限定词时） |
| 占位符 | `/* __DSHP_SLOT:<name>__ */` 这种整行标记 | 插槽、slot 标记 |
| 片段 | `lib/client-src/**` 下的正文文件，被文本装配进产物 | 客户端片段、内联片段、前端模块 |
| 客户端产物 | `client.js`，装配出来给宿主加载的单文件 | 前端 bundle、侧栏、客户端 |
| 装配 | `build-client` 把片段拼成产物的动作 | 拼装、拼接、打包 |
| 演练台 | 红队评测那个界面（侧栏图标 + 主区面板） | 红队台、控制台、RedTeam 台 |
| 设置页 | 宿主设置里的 dsh-purge 一节 | 设置面板、清洗页、清洗面板 |
| 门禁 | 仓库侧的自检命令（`npm run verify` 与三条整洁门禁） | 闸门（见下）、校验 |
| 闸门 | 只用于演练台的「环境适配发送闸门」 | 拿它指仓库门禁 |
| 判据 | 一条可执行的判定语句，失败信息就是它的说明书 | 标准、要求、规范（指同物时） |
| 清洗 | 只作项目名/动作名（dsh 指令权威性清洗），不作界面页名 | 「清洗页」「点清洗」 |
| 已生效 | 补丁状态的一档：字节已是这一版表的目标态，且账本认这条 | 已应用（指界面档位时）、ok、已打过 |
| 待应用 | 补丁状态的一档：这条补丁还有活要干（`pending`），与「跳过」不是同一件事 | 待写入、待清洗（作这一档的名字时）、pending（面向用户时） |
| 按设计跳过 | 补丁状态的一档：本机本来就不需要它（`missing_file` / `off` / `skipped`），不是失败 | 跳过（单说时）、忽略、不适用（指这一档时） |
| 不适用 | 补丁状态的一档：本机宿主没有这条补丁的落点（`na`），分节里不展开 | 跳过（与上一档混用时）、N/A、不支持 |

**三条边界**：Windows 的「控制台」指终端黑框（`hide-console.js`、`shim/silence.js` 里那个），与本表的「演练台」无关，不必改；英文文档用 `console` / `drill` 各自的原词，不必与中文逐词对齐；宿主文档语境（`dsh-native-primer.md`）把宿主概念的 slot 译作「槽位」，那是对原词的翻译，不受本表三分约束。

## 三条日志轨

日志这条线上同物异名最贵的代价是「说日志时读者不知道该开哪份文件」。三条轨各有唯一名字；**不写裸的「日志」**，要么写轨名，要么写完整落点。

| 唯一写法 | 落点 | 一行是什么 | 禁用的同物异名 |
| --- | --- | --- | --- |
| 审计轨 | `<DSH_HOME>/dsh-purge/audit/YYYY-MM-DD.jsonl` | 一次**补丁判定**的证据：带 `seq` / `recordId` / `runId` / `observedTs` / `evidence` | 审计日志（作轨名时）、audit 日志、JSONL 日志 |
| 诊断轨 | `<DSH_HOME>/dsh-purge/logs/diag.jsonl` | 一次**运行期事件**：没有 `seq` / `recordId` / `evidence`，值一律字符串 | 运行日志、诊断日志、diag（作名词时） |
| 内部轨 | `<DSH_HOME>/dsh-purge/logs/desktop.log` | 宿主进程里的**探针**：纯文本，`ISO 时间戳 [标签] k=v` | 桌面日志、purgeLog（作轨名时） |
| 宿主日志 | 宿主自己决定（本仓库只有发射权） | `ctx.logger` 写出去的那条；落点、格式、保留期都不由本仓库定 | 把它叫「第四条轨」——轨的四要素它一项都不由我们定 |

两条口径跟着这三条名字走：**审计轨只记 apply，不记 revert**；**诊断轨只留一代 `.1`，审计轨留 30 天** —— 所以「审计轨有、诊断轨没有」最常见的解释是轮转，不是丢日志。

## 声音锚点

全组文档保持同一个人格，避免某一份突然换成另一种腔调。

- **简体中文**为主，技术词保留英文原形：`apply`、`marker`、`onMiss`、`strictFiles`、`pattern`、`characterization 快照`。
- **断言句优先**，句子短。不用感叹号，不用「我们认为」「可能是这样」这类软化；不确定就写「未实测」。
- **数字必带口径**：谁算的、拿什么算的。没有口径的数字不进文档。
- **段落首句承担主张**：读者靠每段第一句连成主线，首句不许只起铺垫作用。
- **讲为什么优先于讲是什么**；「是什么」交给代码与表格。
- **省略第二人称**：不写「你会发现」「你只需要记住」。

## 序号约定

- **每篇各自从 1 起算**（`## 1`、`### 1.2`），不跨篇连续 —— 跨篇连续会让某一篇的位置变成它的身份，插一篇就全线作废。
- **跨篇引用写篇名 + 节名**，不写「见 2.3 节」。
- **补丁的 `id` 与约束的编号是身份不是位置**：重排章节不影响 `id 46` 与 `PATCH-1`。
- **正文不写序数词**（第一、第二、首先、其次）：次序影响理解就用编号列表，否则用连接词把句子连起来。
- **列表**：只在次序影响理解时编号；并列项用项目符号；不出现只有一项的列表；控制在八项以内。

## 大纲：每篇接什么、留什么

「进」是它接住上一篇留下的问题，「出」是它给下一篇留下的问题。

| 文档 | 它进 | 它出 |
| --- | --- | --- |
| `README.md` / `README.en.md` | 无，读者第一次来 | 「它到底改了宿主什么、凭什么敢改」→ 文档索引 |
| `docs/文档索引.md` | README 已经让人想往深处看，但不知道有哪几份 | 每份的一句话；想知道编号去约束索引，想知道文件放哪去布局约定 |
| `docs/术语账本.md`（本文件） | 读者开始读到第二份文档，名字开始重复出现 | 全组共用的名字与主线 |
| `docs/约束索引.md` | 「改错了会怎样」 | 每条约束的判定载体；失效时删行不改写历史 |
| `docs/布局约定.md` | 「新文件该放哪、能不能超 800 行」 | 能判的判据已落成门禁，判不了的留给评审 |
| `AGENTS.md` | 要动这个仓库的代码 | 先查图、先看大文件、生成链只写不读、注释规范 |
| `release-notes.md` | 升级前想知道改了什么 | 三条不兼容变更 |
